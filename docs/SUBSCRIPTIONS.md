# In-app subscription management (manual billing)

The workspace navigation now includes **Subscription**. Current plan, recorded status, trial/paid expiry, current access, active seats and enquiry limits come from the agency's database records. Pending seat reservations are shown to owners. Prices remain **Price on request** because recurring rates, taxes, billing terms and AI allowances have not been finalised. No provisional sales price is silently made a binding checkout price.

Owners can request Start subscription, Renew, Upgrade or Cancel at period end. The authenticated API validates the plan and request type, rechecks the current user role and derives agency ID from the session, not submitted input. Requests are recorded in the existing activity table; the same request is deduplicated for 24 hours under an agency row lock. Expired/inactive owners can request renewal. Demo and non-owner requests are denied. No migration or new credentials are required.

Agency owners see their recent request history. The existing MFA-protected service-operator `/admin` screen shows recent requests for each agency. Requests do not send email notifications. Operators must check requests and independently verify any agreed business payment before updating plan/status/expiry. Cancellation requests do not automatically cancel service, issue refunds or change expiry; the operator must handle the agreement and confirm the outcome. Request history records submission, not payment or fulfilment.

There is no card checkout, payment gateway, autopay, tax invoice generation or verified payment ledger for SaaS fees in this change. Travel booking receipts are distinct from subscription payments. Configure SUPPORT_EMAIL for a billing contact. Never ask clients to submit card/bank credentials in request notes. Recurring checkout later needs a chosen provider, verified server webhooks, pricing/tax configuration and payment/reconciliation records. Client clicks or browser redirects must never activate paid access.

Review: login as an agency owner → Subscription → select a plan/request → Request subscription review. Confirm plan/status does not change, the request appears in Recent requests, and the service operator sees it in `/admin`. Demo displays the page read-only. Agents/managers can view plan information but cannot request changes. Windows users need the latest branch files and a restarted app; production deployment is separate.

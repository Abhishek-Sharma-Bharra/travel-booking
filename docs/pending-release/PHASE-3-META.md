# Phase 3 — Meta Ads (Razorpay deferred)

Implemented inside the existing application: tenant-scoped encrypted advertising connections, one-use owner/session-bound OAuth state, authorized account selection, daily ad-set/campaign spend/impressions/clicks, source currency/timezone, resumable paginated backfills, atomic snapshot replacement, error/expiry status and local disconnect. Integrations navigation is unavailable to agents; the public demo cannot connect or sync.

Private setup: `INTEGRATION_ACTIVE_KEY`, `INTEGRATION_ENCRYPTION_KEYS` (JSON key-version → 64 hex characters), `META_APP_ID`, `META_APP_SECRET`, and an explicitly reviewed `META_GRAPH_VERSION`. Never reuse the auth secret as the vault key. Retain previous key versions during rotation. Register the exact `/api/integrations/meta/callback` redirect for the configured HTTPS app origin. Complete Meta app/business review and permitted `ads_read` access; configuration is not proof of provider approval. No unrestricted API-key form is provided to agency users.

OAuth code exchange and account enumeration happen server-side. State is hashed, ten-minute, tenant/user-bound and consumed once. Credentials use AES-256-GCM with tenant/provider/connection associated data. Read responses never include ciphertext, tokens or staged data. The authorized account list is loaded explicitly; the server rechecks authorization when selecting. Local disconnect removes credentials, blocks new work and cancels unfinished staging; revoke app access at Meta separately. Disconnect remains possible when SaaS subscription has expired.

Backfill one window of 1–31 **closed account-calendar days**. Each request processes at most three pages and checkpoints the remaining cursor. Continue the same window to resume; phase 6 adds background scheduling. Per-run facts are staged, keyed by day/campaign/ad set and bounded to 5,000 rows. Only complete snapshots replace previous facts, including legitimate zero-result windows. Failure/revocation/revision mismatch preserves previous complete data. URLs from provider paging are never followed; only validated cursors are used against the fixed Graph host. No leads, conversions or exchange rates are fabricated. The Integrations table displays source-native metrics separately from manual monthly spend; campaign-level CRM CPL remains unavailable without explicit matching attribution IDs.

Verification at phase checkpoint: TypeScript passed; two focused tests passed with mocked transport, covering vault context/tamper protection, exact micros, cross-agency/role denial, OAuth replay/foreign state rejection, authorized account selection, native USD/timezone preservation, corrected resync without duplicates, failed second-page preservation, expired token status and expired-subscription disconnect. No real OAuth, ad account reads or campaign changes were performed. Official app/API permissions and live response compatibility still require approved staging credentials and validation.

# Phase 4 — Google Ads

Extends the existing connection vault/sync engine with Google OAuth authorization-code + PKCE, offline consent, encrypted refresh tokens, permitted customer enumeration, manager-to-client account selection and `login-customer-id`, campaign/day cost_micros, clicks, impressions and separately labelled Google-reported conversions. Token refresh uses optimistic ciphertext fencing so a concurrent refresh/revocation cannot overwrite credentials. No provider conversion is treated as a CRM booking or combined with another provider's definition. Monetary micros remain exact strings/BigInt; no currency conversion is invented.

Configure approved Google OAuth client/consent, Ads developer-token access and exact `/api/integrations/google/callback`, then privately set `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_ADS_DEVELOPER_TOKEN`, an explicitly supported `GOOGLE_ADS_API_VERSION`, and the integration vault keys. Google Ads uses the provider-supported adwords scope; application operations are read-only reports, not campaign mutations. Access tiers, account hierarchy and consent requirements require current provider approval. No private credentials go into frontend forms.

Source metrics preserve account currency and timezone. Backfill/retry/snapshot limits are the same as Meta. Conversions retain the label GOOGLE_ADS_PRIMARY_CONVERSIONS_AS_REPORTED; underlying conversion-action/window definitions may differ, so they are displayed individually, never summed into CRM conversion or cross-account ROI. A missing integration/permission is not zero spend. Phase 1 manual monthly KPI definitions remain intact; automatic joining to CRM campaigns requires explicit matching attribution and is not fabricated.

Checkpoint evidence: TypeScript and production build passed. Three ads/vault tests passed with mocked transports, including PKCE verification, account authorization denial, manager hierarchy headers, encrypted offline refresh, exact cost_micros and 1.5 provider conversions kept separate from bookings. No real OAuth/account calls or ads changes occurred.

# Phase 6 — durable automation (disabled until configured)

Agency-level switches control advertising sync, booking confirmations, balance/departure reminders, internal KPI summaries and internal integration alerts. Defaults are all off. Owners change settings; managers read history; agents cannot access automation administration. Disabled/expired/demo tenants cannot execute new work. Policy revisions cancel pending jobs. Nothing is sent merely by saving controls.

PostgreSQL stores jobs, attempts, availability, leases, outcomes and sanitized errors. Unique agency/business keys prevent repeated daily planning. Claiming uses FOR UPDATE SKIP LOCKED; fencing rejects stale runners and expired leases. Provider failures back off with jitter and go DEAD after five failures; authorization/policy failures go BLOCKED. Owner retry is available only for safe internal/read-only jobs. Message retries are blocked pending provider reconciliation. Provider acceptance is not delivery or a verified payment.

`npm run automation:run` is the private operator runner: bounded agency planning and up to ten job executions. A private scheduled caller may POST `/api/automation/run` with `Authorization: Bearer AUTOMATION_RUNNER_SECRET` and JSON `{ "schedule": true, "cursor": "" }`; keep this secret separate and 32+ random characters. The response includes the next agency cursor: continue while present. Subsequent schedule:false calls drain one persisted job each. Provision the scheduler in staging and monitor backlog/DEAD/BLOCKED counts; the app does not schedule itself merely because it is deployed. Do not run migrations from the runner.

Planners paginate accounts/bookings into durable child jobs. Ads synchronize the most recent closed account-local day; historical outage gaps require explicit backfill in Integrations. Summaries use yesterday's agency-local calendar boundaries and existing truthful KPI definitions, with unavailable metrics kept unavailable. They are in-app results, not unapproved outgoing emails. Reminders plan/execute only 09:00–17:59 agency time, expire at the end of that local day, respect opt-out/templates/balance and recipient frequency caps. Confirmations cover recently created bookings; stale/missed periods need operator review. No blanket historical messages are sent.

Razorpay and verified-payment reconciliation remain explicitly deferred. No production runner, provider credentials or live send approval were added. Real callbacks, scheduler timing, throughput, provider outages and token expiry need staging rehearsal. The automation outbox is at-least-once internally; exactly-once external message delivery is not promised. Never requeue an uncertain provider send automatically.

Verification: `tests/automation.test.ts` checks default-off, duplicate schedule keys, concurrent claim exclusion, expired lease reclamation, obsolete-runner fencing, tenant/role denial, global send blocks, retry backoff/dead-letter and policy cancellation. Provider traffic uses a fictional test transport.

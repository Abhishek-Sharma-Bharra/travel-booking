# Market pilot operations release — 27 November 2026

## Scope and status

The earlier `c44e5de` release was pushed to main and GitHub checks passed. This increment adds private supplier/contract records, explicit automatic enquiry assignment, tool discovery and permission hardening. It does not complete every module in the Advanced ERP brief or activate a fully automated paid SaaS. A local test or CI pass is not a live Cloudflare smoke test.

## Where the features are

1. Public homepage: VASHISHT branding, business sections, interactive demo, premium monthly/annual proposals and light/dark preference.
2. Agency sign-in → Overview: **Tools ready for your daily operations** links to CRM review, suppliers/contracts and itinerary costing.
3. **CRM review**: exact-contact candidates, individual enquiry segments, lost reasons, overdue follow-ups and current recorded team/source outcomes. No automatic contact merging.
4. **Suppliers**: private directory above the existing manual ledger; hotel, transport, DMC, sightseeing, guide and other contacts. Owners/managers can create, edit or archive profiles, maintain INR negotiated-rate and contract terms, and inspect immutable prior revisions. Agents cannot obtain private contract data through the API. Directory profiles do not rewrite old supplier-name ledger entries.
5. **New enquiry → Assigned to → Auto · least open enquiries**: owner/manager explicitly opts in for that newly created New-stage enquiry. Backend selects an active same-agency teammate using open-stage counts with guarded/serializable writes. Closed leads do not add workload; existing assignments, bulk imports and campaign-specific routing do not change silently. This is not a global campaign assignment policy.
6. Itineraries, quotations, booking records, collections, hotel and bus/car workspaces retain their existing workflows. Guided assistants remain available; live providers are gated separately.

## Reliability and security

- Fresh database role/tenant/disabled-account checks; only OWNER, MANAGER and AGENT are recognised for agency access. Database role constraints remain intact. PostgreSQL workspace reads now refresh the role before selecting/redacting fields; a forged/stale owner actor cannot broaden an agent's read scope.
- Supplier requests use session-derived tenancy, owner/manager authorization, same-origin JSON writes, bounded bodies/fields, rate limits, private/no-store responses and parameterized SQL. Histories are append-only and tenant-bound with foreign keys.
- Atomic profile/version/audit writes. Stable request keys and payload hashes detect duplicate or changed replays; concurrent saves use revision checks. Confirmed database rollback errors may be retried within a bounded limit. Unknown network outcomes are not blindly reissued. The UI freezes an uncertain draft and offers same-key retry or explicit record review.
- Pages JSON protection now includes supplier and billing endpoints; upstream HTML errors become sanitized JSON with a correlation ID. OAuth redirects stay untouched.
- Existing CSRF/body limits, booking/payment idempotency, MFA-only platform administration, card-data exclusion, assistant tool validation and permission redaction remain enforced. A clean dependency scan is not a penetration-test certificate.

## Migrations and limits

Additive D1 **0011_supplier_directory.sql** and PostgreSQL **20261127000000_supplier_directory** add AgencySupplier and AgencySupplierVersion only. No ORM baseline rewrite or destructive operation. Existing paid agency records are seeded *before* the migration in upgrade tests and retain plan/status/expiry afterward. Old ledgers/bookings/subscriptions are not migrated or repriced.

Initial directory limits: 200 profiles (including archived), 30 immutable revisions per profile, bounded field/payload size, 20 profiles per list page. Reaching limits requires capacity review, not automatic purchase. Contracts use INR and recorded unit/rate/dates/terms; no live supplier availability, tax certification, order, message or payment is created by saving them.

## Required release steps

Build the reviewed commit using `npm run cloudflare:build`; its dry-run worker budget guard must pass. The existing Worker deploy command must remain `npm run cloudflare:release:worker`: verify the D1 restore bookmark, apply reviewed outstanding migrations, then deploy the private Worker. Deploy Pages from the same main revision/output `cloudflare/pages-dist`. Do not seed/reset production. Verify both build identifiers, health, real owner login, supplier save/history and a test enquiry before onboarding paying clients. Browser refresh: Ctrl+Shift+R.

Rollback: application rollback can leave these additive tables and immutable journals in place. Never delete the journals or restore a database blindly over new customer writes. Keep the pre-release restore bookmark and reconcile any confirmed writes first.

## Commercial launch blockers

Email delivery and mandatory verification have not been proven on the production origin. The versioned Worker config currently has REQUIRE_EMAIL_VERIFICATION=false; that is a pilot limitation, not full identity readiness. Use EMAIL-SETUP-HI.md before requiring verification so new/existing users are not stranded.

Razorpay merchant account/test proof and final billing/tax/refund terms remain missing; SaaS test billing and live hotel payments stay disabled. Paid AI needs an approved server project/key, model pilot and measured budget. Voice, WhatsApp and ads require provider approvals, consent/delivery validation and remaining implementation (including the D1 ads port), not just keys.

Structured purchase orders, compliant GST invoices/credit notes, full customer portal/signed acceptance, branch policies, global assignment policy, advanced price rules/multi-currency, validated ML and hosted load/restore rehearsal remain separate unfinished work. Do not advertise these as working today.

This increment adds no paid service or infrastructure. Storage/query costs still depend on real traffic and existing Cloudflare allowances; no client capacity or zero-error guarantee is inferred from local tests.

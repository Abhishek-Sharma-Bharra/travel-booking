## Migrations and rollout

D1 `0008_workspace_assistant.sql` and a matching PostgreSQL additive migration create `WorkspaceAssistantUsage` with tenant/request uniqueness, actor identity, state/mode/tool/model, reserved/reported tokens, timestamps and safe failure codes. No prior migration or Prisma baseline is rewritten. New backend tools require `WORKSPACE_ASSISTANT_ENABLED=true`; paid routing additionally requires `PAID_AI_ENABLED`, `WORKSPACE_ASSISTANT_LIVE_APPROVED`, an explicit server-managed agency allowlist and the key. This avoids automatic paid opt-in from another module's approval. Do not enable either in production without the paired migration and approved deployment.
